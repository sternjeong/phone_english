03 · Reference Research

레퍼런스 리서치 — 헤이링 (HeyRing)

개발사하이퍼노바 (HYPERNOVA)
평점4.7 / 5.0 (2,200+)
차트교육 카테고리 13위
공식 사이트heyring.app

3개월 만에 매출 1억 원 달성, 교육 앱 전체 6위 기록했다는 보도 있음. iOS(App Store) / Android 모두 출시.

내가 전화 거는 게 아니라, AI가 먼저 전화를 건다. — 능동적으로 앱을 켜야 하는 부담을 없애고, 정해진 시간에 AI 원어민 친구가 전화를 걸어와 받기만 하면 영어 회화 연습이 시작되는 구조

핵심 기능

  1. 선(先)전화 시스템 — 사용자가 설정한 시간에 AI가 먼저 전화 (최대 3회까지 재시도). 안 받으면 계속 찾아옴.
  2. 맞춤형 AI 원어민 친구 — 관심사·성격·취미를 반영한 페르소나. 이전 대화를 기억해 친구처럼 이어감.
  3. 실시간 보조 — 막히면 한국어로 물어볼 수 있고, 힌트/질문하기로 다음 문장을 이어감.
  4. 리스닝 보조 — AI 답변이 영어+한국어 동시 표시.
  5. 실시간 패러프레이징 — 발화를 더 자연스러운 원어민 표현으로 즉시 교정 + 이유 설명.
  6. 통화 후 리포트 — 발음/운율/유창성 분석, 그래프로 진도 시각화.
  7. 통화 시간 — 기본 10분, 무제한 연장 가능.

사용 흐름

  1. 앱 설치 및 가입
  2. 온보딩에서 관심사/성격/희망 통화 시간 설정
  3. 설정 시간에 AI가 전화 (최대 3회 재시도)
  4. 전화 수신 → 대화 시작 (영한 자막, 힌트/질문, 실시간 교정)
  5. 통화 종료 → 자동 리포트 생성
  6. 리포트 복습

  • 상세한 피드백 — "스픽보다 낫다"는 비교 후기

불만 / 요청 사항

  • 페르소나/메모리 시스템 — 캐릭터 설정 + 장기 기억
  • 실시간 영한 동시 자막
  • 실시간 교정(패러프레이징) 엔진
  • 통화 녹음/전사 저장 → 리포트 후처리
  • 스케줄러/알림 — 전화 트리거, 재시도 로직
  • 구독/결제 시스템
  • 온보딩 & 프로필 관리
04 · Decisions

결정 사항

결정
레퍼런스는 헤이링. 핵심 기능/플로우를 최대한 유사하게 구현한다.
카피 범위
UI/UX(화면 구성·색감·레이아웃·인터랙션)까지 최대한 비슷하게 재현. 단 브랜드명/로고는 별도로 정함 — 상표 그대로 도용하지 않음. 서비스명은 이후 "Good Morning"으로 확정.
전화 구현
실제 PSTN 없이 인앱 콜 UI 시뮬레이션. 수신 화면·받기/거절·통화 화면 모두 웹앱 내 재현, 실제 전화망 연동 없음.
플랫폼
웹 앱으로 시작. 브라우저에서 바로 접근. 모바일 앱 전환은 추후 고려.
전화 트리거
예약 시각 + 웹푸시가 아니라, "전화 걸기" 버튼을 누르면 즉시 수신 화면이 뜨는 온디맨드 방식. 백그라운드 스케줄러/푸시 인프라 불필요.
음성
처음부터 음성 포함. 브라우저 내장 Web Speech API(SpeechRecognition + SpeechSynthesis) 사용 — 무료, 별도 서버/키 불필요.
LLM
Gemini API(Google AI Studio)로 대화 생성. 2차 갱신 — 처음엔 OpenAI였으나 사용자 요청으로 전환.
기술 스택
Next.js + TypeScript — 프론트/백엔드(API Route)를 한 프로젝트에서 해결. 배포는 추후 Vercel 등 고려.
계정/결제
MVP에서는 둘 다 생략. 로그인 없이 바로 사용, 결제 플로우 없음.
05 · Scope

MVP 기능 범위 (1차 확정)

  1. 온보딩 — AI 페르소나(이름/성격/관심사) 간단 설정, 최소 형태로 시작
  2. 홈 화면 "전화 걸기" 버튼 → 인앱 수신 전화 화면 UI (헤이링 스타일 수신/받기/거절)
  3. 통화 화면 — 마이크 발화 → STT(Web Speech API) → Gemini API 응답 생성 → TTS 재생, 영한 자막 동시 표시
  4. 대화 중 힌트/질문하기 버튼
  5. 실시간 교정(패러프레이징) — 더 자연스러운 표현 제안 + 이유 설명
  6. 통화 종료 후 자동 리포트 — 요약, 교정된 표현 목록, 간단 피드백
  7. 계정/결제 없이 세션·localStorage 기반 최소 히스토리
06 · Architecture

아키텍처 초안

FRONTEND
Next.js(App Router) + TypeScript, React 컴포넌트로 홈 / 수신화면 / 통화화면 / 리포트화면 구성
BACKEND
Next.js API Route에서 Gemini API 호출 (대화 생성 · 교정 · 리포트 요약) — API 키는 서버사이드에서만 사용
VOICE
브라우저 Web Speech API를 클라이언트에서 직접 사용, 서버 경유하지 않음
STATE
초기엔 React state + localStorage, DB는 필요해지면 추후 도입

08 · UI/UX Teardown

실제 앱 UI/UX 상세 분석

사용자가 헤이링 앱을 직접 사용하며 캡처한 스크린샷 19장 기반. 텍스트 리서치보다 훨씬 정확한 1차 자료이므로 UI 구현 시 최우선 기준으로 삼는다.

전체 톤 — 기존 가정 수정

  • 홈/통화 관련 화면은 블랙 배경이 압도적. 리포트 목록/보관함/발화기록 등 일부 데이터 화면만 화이트 배경 — 화면별 다크/라이트 혼용.
  • 포인트 컬러는 그린/민트 계열(통화 버튼, 패러프레이징 완료 태그, 유창성 게이지) — "배경이 민트"가 아니라 블랙 바탕 + 그린 포인트가 정확한 설명.
  • 발음 점수는 색상으로 구분 — 초록(좋음) / 노랑(보통) / 빨강(개선 필요), ELSA Speak류 단어별 채점과 유사.
핵심 인터랙션
확인 필요 / 추정

SCREEN 01 / 11

홈 화면

  • 블랙 배경. 상단 좌우 "일정" / "학습" 텍스트 탭, 우측에 스트릭 카운터(🔥 0)와 프로필 아이콘.
  • 화면 정중앙에 AI 캐릭터 이름이 매우 큰 손글씨체로 표시 (예: "Haze").
  • 하단 바: 좌측 일정(캘린더) · 중앙 큰 원형 초록 통화 버튼(돌출) · 우측 학습(파형) — 3아이콘 탭바 구조.
SCREEN 02 / 11

일정(스케줄) 화면

  • "오늘 일정" 라벨 + 큰 시간 텍스트 + 초록 체크 아이콘.
  • "반복 일정" 섹션 + "수정" 링크, 카드형 리스트로 반복 예약 표시(예: "토요일 19:00").
  • 참고용 — MVP는 온디맨드 트리거로 대체하므로 이 화면 로직은 다르게 구현.
SCREEN 03 / 11

리포트 목록 (통화 / 보관 탭)

  • 화이트 배경. 상단 탭 "통화" / "보관" — 선택된 탭은 검은 필.
  • 통화 탭 빈 상태: 문서 아이콘 + "아직 통화 리포트가 없어요" + 부연 문구.
  • 보관 탭 빈 상태: 폴더 아이콘 + "표현"/"문장" 서브 토글.
SCREEN 04 / 11

학습 — 발화 기록

  • 블랙 배경. 제목 "발화 기록", 큰 통계 "🔥 0 단어", CTA "이번주도 달려볼까요?"
  • 월별 캘린더, 날짜마다 물방울/불꽃 아이콘으로 스트릭 표시(히트맵 캘린더).
  • 하단 통계 카드 2개: "통화 N회" / "학습 N분".

SCREEN 06 / 11

수신 전화 / 통화 시작

  • 상단 좌측 전구(힌트) 아이콘, 우측 설정 아이콘, 중앙 타이머 + AI 이름.
  • AI 첫 인사가 영어 → 한국어 순으로 순차 표시.
  • 온보딩 툴팁: 점선 화살표가 힌트 아이콘을 가리키며 "대화가 막힐 때는 힌트를 사용해보세요" 안내.
  • 각 AI 발화 아래 깃발(신고)/북마크(저장) 아이콘.
SCREEN 07 / 11

통화 중 화면 — 핵심 인터랙션

  • 사용자 발화: 오른쪽 정렬 말풍선으로 즉시 표시(STT), 아래 "패러프레이징 하고 있어요…" → 완료 시 초록 "👍 패러프레이징" 필로 전환.
  • AI 발화: 왼쪽 정렬, 타이핑 스트리밍 → 완료 후 영문 아래 회색 작은 글씨로 한국어 번역(영한 동시 자막).
  • 하단 컨트롤: 빨간 "종료" / 회색 "말하기"(마이크, PTT 추정) / 회색 "주제"(도형 아이콘).
SCREEN 08 / 11

주제(topic) 선택 다이얼

  • "주제" 버튼 → 블러 배경 원형 다이얼 오버레이.
  • 중앙에 현재 선택 항목 + 설명 + "선택" 버튼.
  • 방사형 메뉴: 나(사람) / 커리어(새싹) / 관계(하트) / 감정(스마일), 중앙 X로 닫기.
SCREEN 09 / 11

통화 종료 직후 요약

  • 완전 블랙 배경, 거대한 숫자(예: "139")가 중앙에 크게 표시.
  • 아래 필 라벨 "🔥 내가 말한 단어" — 통화 직후 임팩트 있는 축하/요약 스크린.
SCREEN 10 / 11

리포트 상세

  • 상단 핑크 긴급 배너 "⏰ 할인 혜택이 곧 사라져요 04:43" — 실시간 카운트다운, 통화 직후 구독 유도 UX.
  • 제목은 AI가 생성한 대화 주제명(예: "군대 동기와의 솔직한 대화") + 날짜.
  • 스탯 필 "🔥139"(단어 수) + 초록 필 "나의 유창성".
  • 반원형 게이지(0~100) — 복습 전 "?" 잠금 상태. 발음/운율/유창 3개 스탯 카드(복습 전 00%).
  • "✨ 내게 딱 맞는 원어민 표현" 캐러셀(예: 7개 중 1/7) — 표현 + 뜻 + 예문(하이라이트) + 북마크 + "🎤 연습".

사용자 요청: "streamlit처럼 주소 하나로 항상 접근" + "로그인해서 로그가 쌓이도록". MVP의 "계정 없음, localStorage만" 결정을 뒤집는 변경.

아키텍처

① useAsync가 렌더 중 ref를 변경해 React Compiler가 차단 → 클로저 방식으로 단순화. ② 로그인 게이트가 실제로는 리다이렉트를 안 함(curl로 발견, 비로그인 상태에서 200 OK) → NextAuth authorized 콜백 추가로 해결. 둘 다 정적 검사로는 못 잡는 버그.
Next.js 16
middleware.ts가 deprecated — proxy.ts로 이름 변경 (빌드 경고 + 번들된 Next.js 문서로 확인).
Google → 패스코드 전환
Google Cloud Console에서 OAuth 클라이언트 생성이 반복적으로 실패("OAuth 구성을 만드는 중에 오류가 발생했습니다") → 어차피 1인 전용 서비스라 Google OAuth를 걷어내고 AUTH_PASSCODE 하나로 로그인하는 Credentials 프로바이더로 교체. Playwright로 틀린/맞는 비밀번호 둘 다 라이브 검증 완료.

사용자가 직접 해야 하는 것 (8차 갱신으로 축소됨)

  1. Vercel에 레포 연결 → Storage에서 Postgres 추가(자동으로 POSTGRES_URL 주입)
  2. AUTH_SECRET 생성 및 등록
  3. AUTH_PASSCODE(원하는 로그인 비밀번호) 등록
  4. GEMINI_API_KEY도 Vercel 환경변수에 등록 (로컬에만 있으면 배포본은 501)
