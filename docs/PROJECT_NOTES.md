### 핵심 컨셉
"내가 전화 거는 게 아니라, AI가 먼저 전화를 건다" — 능동적으로 앱을 켜야 하는 부담을 없애고, 정해진 시간에 AI 원어민 친구가 전화를 걸어와 받기만 하면 영어 회화 연습이 시작되는 구조.

### 핵심 기능
1. **선(先)전화 시스템**: 사용자가 설정한 시간에 AI가 먼저 전화 (최대 3회까지 재시도). 전화를 안 받으면 계속 찾아옴.
2. **맞춤형 AI 원어민 친구**: 사용자의 관심사·성격·취미를 반영해 페르소나를 가진 AI와 대화. 이전 대화 내용을 기억해서 친구처럼 이어감.
3. **실시간 보조**: 대화가 막히면 한국어로 물어볼 수 있고, 힌트/질문하기 기능으로 다음 문장을 이어갈 수 있음.
4. **리스닝 보조**: 상대방(AI) 답변이 영어+한국어 동시 표시.
5. **실시간 패러프레이징**: 사용자의 발화를 더 자연스러운 원어민 표현으로 즉시 교정 + 이유 설명.
6. **통화 후 리포트**: 발음/운율/유창성 등을 분석한 학습 리포트 자동 생성, 유창함 그래프 등으로 진도 시각화.
7. **통화 시간**: 기본 10분, 무제한 연장 가능.

### 사용 흐름 (온보딩 → 리포트)
1. 앱 설치 및 가입
2. 온보딩에서 관심사/성격/희망 통화 시간 등 설정
3. 설정 시간에 AI가 전화 (최대 3회 재시도)
4. 전화 수신 → 대화 시작 (영어+한국어 자막, 힌트/질문 버튼, 실시간 교정)
5. 통화 종료 → 자동 리포트 생성 (표현 교정, 발음/유창성 분석)
6. 리포트 복습

### 기술적으로 추정되는 구성 요소 (카피 시 구현 필요 항목)
- 예약된 시간에 전화를 "거는" 기능 → 실제 PSTN 전화(Twilio 등 텔레포니 API) or 인앱 VoIP/콜 UI 시뮬레이션 (방식 결정 필요, 아래 열린 질문 참고)

- 페르소나/메모리 시스템: 사용자별 AI 캐릭터 설정 + 장기 기억(이전 대화 요약 저장)
- 실시간 자막/번역 (영어+한국어 동시 표시)
- 실시간 교정(패러프레이징) 엔진
- 통화 녹음/전사 저장 → 후처리로 리포트 생성 (발음, 유창성, 문법 교정)
- 스케줄러/알림 (전화 걸 시간 트리거, 재시도 로직)
- 구독/결제 시스템 (인앱결제)
- 사용자 온보딩 & 프로필 관리

## 결정 사항 (Decisions)
- 레퍼런스: 헤이링. 이 앱의 핵심 기능/플로우를 최대한 유사하게 구현하는 것을 목표로 한다.
- **카피 범위**: UI/UX(화면 구성, 색감, 레이아웃, 인터랙션)까지 최대한 비슷하게 재현. 단, 브랜드명/로고는 별도로 정함(상표 그대로 도용은 하지 않음). → 새 서비스명 정하기가 To-do로 남음.
- **전화 걸기 구현 방식**: 실제 PSTN 통신 없이 **인앱 콜 UI 시뮬레이션**으로 구현. (수신 전화 화면 UI, 받기/거절 인터랙션, 통화 중 화면을 모두 웹앱 내에서 재현하되 실제 전화망 연동은 하지 않음)
- **플랫폼**: **웹 앱**으로 시작 (브라우저에서 바로 접근). 모바일 앱 전환은 추후 고려.

- **전화 트리거 방식**: 예약 시각 + 웹푸시 알림이 아니라, 사용자가 앱에서 "전화 걸기" 버튼을 눌러 즉시 인앱 수신 화면이 뜨는 **온디맨드 방식**. (백그라운드 스케줄러/푸시 인프라 불필요 → MVP 단순화)
- **음성 대화**: 처음부터 음성 포함. 브라우저 내장 **Web Speech API** (SpeechRecognition + SpeechSynthesis) 사용 — 별도 STT/TTS 서버·API 키 불필요, 무료.
- **LLM**: **Gemini API**(Google AI Studio)로 대화 생성. (2026-08-17 2차 갱신: 처음엔 OpenAI로 정했으나 사용자가 Gemini로 전환 요청 — 아래 "진행 관련 메모"의 키 관련 코멘트 참고)
- **기술 스택**: **Next.js + TypeScript** — 프론트엔드와 API 라우트(백엔드)를 한 프로젝트에서 해결. 배포는 추후 Vercel 등 고려.
- **로그인/결제**: MVP에서는 **둘 다 생략**. 계정 시스템 없이 바로 사용, 결제 플로우 없음.

## MVP 기능 범위 (확정)
1. 온보딩: AI 페르소나(이름/성격/관심사) 간단 설정 — 최소 형태로 시작 가능
2. 홈 화면에서 "전화 걸기" 버튼 → 인앱 수신 전화 화면 UI (헤이링 스타일: 수신 화면, 받기/거절)
3. 통화 화면: 마이크로 말하면 STT(Web Speech API)로 텍스트 변환 → Gemini API로 AI 응답 생성 → TTS(SpeechSynthesis)로 음성 재생, 화면에는 영어+한국어 자막 동시 표시
4. 대화 중 힌트/질문하기 버튼 (막힐 때 도움)
5. 실시간 교정(패러프레이징): 사용자의 발화를 더 자연스러운 표현으로 제안 + 이유 설명
6. 통화 종료 후 자동 리포트: 대화 요약, 교정된 표현 목록, 간단한 피드백
7. (계정/결제 없음 — 세션/로컬 상태 기반으로 리포트 히스토리는 브라우저에 저장하는 정도로 최소 구현)

## 실제 앱 UI/UX 상세 분석 (사용자 제공 스크린샷 19장 기반, 2026-08-17)

사용자가 헤이링 앱을 직접 사용하며 캡처한 스크린샷을 제공. 텍스트 리서치보다 훨씬 정확한 1차 자료이므로 **아래 내용을 UI 구현 시 최우선 기준으로 삼는다.**

### 전체 톤 (중요 — 기존 가정 수정 필요)
- 홈/통화 관련 화면은 **블랙 배경 기반**이 압도적. 리포트 목록/보관함/발화기록 등 일부 데이터 화면만 **화이트 배경**을 사용 (화면에 따라 다크/라이트 혼용).
- 포인트 컬러는 **그린/민트 계열** (통화 버튼, "패러프레이징 완료" 태그, 유창성 게이지 그라데이션 등) — 배경이 민트인 게 아니라 **블랙 바탕 + 그린/민트 포인트**가 정확한 설명. (앞서 정한 "밝고 민트한 느낌"과는 다름 — 아래 열린 질문 참고)
- 발음 점수는 색상으로 구분 표시 (초록=좋음, 노랑=보통, 빨강=개선 필요) — ELSA Speak류 단어별 색상 채점과 유사.

### 화면별 상세

**1. 홈 화면**
- 블랙 배경. 상단 좌우: "일정" / "학습" 텍스트 탭. 우측 상단에 스트릭 카운터(🔥 0)와 프로필 아이콘.
- 화면 정중앙에 AI 캐릭터 이름이 매우 큰 손글씨체(cursive)로 표시 ("Haze").
- 하단 바: 좌측 "일정"(캘린더 아이콘) · 중앙 큰 원형 초록 통화 버튼(수화기 아이콘, 돌출된 형태) · 우측 "학습"(파형 아이콘) — 3개 아이콘이 하단 탭바처럼 배치되고 중앙 버튼이 가장 크고 튀어나와 보임.

**2. 일정(스케줄) 화면**
- 뒤로가기 화살표. "오늘 일정" 라벨 + 큰 시간 텍스트("오후 12:11") + 초록 체크 아이콘.
- "반복 일정" 섹션 + 우측 "수정" 링크. 카드형 리스트로 "토요일 19:00" 같은 반복 예약 표시.
- (참고: 실제 예약 시간이 있지만, 우리 MVP는 온디맨드 방식으로 가기로 결정했으므로 이 화면은 참고만 하고 트리거 로직은 다르게 구현)

**3. 리포트 목록 (통화 / 보관 탭)**
- 화이트 배경. 상단 탭 "통화" / "보관" (선택된 탭은 검은 필 형태).
- 빈 상태: "통화" 탭은 문서 아이콘 + "아직 통화 리포트가 없어요" + "꾸준히 통화하면서 리포트를 차곡차곡 쌓아보세요"
- "보관" 탭은 폴더 아이콘 + "아직 저장한 표현이 없어요", 상단에 "표현"/"문장" 서브 토글(검은 필)

**4. 학습 — 발화 기록 화면**
- 블랙 배경. 제목 "발화 기록". 큰 통계 "🔥 0 단어".
- CTA 버튼 "이번주도 달려볼까요?"
- 월별 캘린더(예: "8월") — 요일 헤더(월~일), 날짜마다 작은 물방울/불꽃 아이콘으로 그날의 스트릭/활동 여부 표시 (일종의 히트맵 캘린더).
- 하단 통계 카드 2개: "통화 1회" / "학습 1분"

**5. 온보딩/마케팅 티저 화면**
- 블랙 배경, 헤드카피 "대화를 분석해 더 유창하게 말할 수 있게 도와줄게요"
- 겹쳐진 카드 스택으로 실제 리포트 예시 미리보기: (a) "check out / 확인하다" + 내가 말한 문장에서 교정 단어("recommended")를 오렌지로 하이라이트, (b) "종종 머뭇거리고 있어요" + 자연스러운 속도 vs 느린 속도 비율 바(80%/20%) + 문장 길이별 분포(긴/보통/짧은 문장 개수·비율)

**6. 수신 전화 / 통화 시작 화면**
- 블랙 배경. 상단 좌측 전구(힌트) 아이콘, 우측 슬라이더(설정) 아이콘, 중앙 상단 타이머, 그 아래 AI 이름("Haze").
- AI의 첫 인사가 자막처럼 순차 표시: 영어 문장 → 한국어 번역 순으로 나타남 (예: "Oh—hey, hesse! You're here! I'm Haze." / "어—안녕, hesse! 왔네! 나 Haze야.")
- **온보딩 툴팁**: 점선 화살표가 좌상단 전구 아이콘을 가리키며 "대화가 막힐 때는 힌트를 사용해보세요" 안내 — 첫 통화 시 기능 안내 오버레이가 뜸.
- 각 AI 발화 아래 작은 아이콘(깃발=신고, 북마크=저장)이 붙음.

**7. 통화 중 화면 (핵심 인터랙션)**
- 상단 구성은 6번과 동일(힌트 아이콘 좌상단, 설정 아이콘 우상단, 타이머, AI 이름).
- **사용자 발화**: 오른쪽 정렬 진한 회색 말풍선으로 즉시 표시 (STT 결과로 추정). 말풍선 아래 작게 "패러프레이징 하고 있어요…" 텍스트가 붙어 AI가 표현을 분석 중임을 표시.
- 패러프레이징이 완료되면 그 텍스트가 **초록색 필 "👍 패러프레이징"** 라벨로 바뀜 (사용자의 표현이 이미 자연스러웠다는 승인 표시로 추정 — 교정이 필요한 경우 대안 표현이 노출될 가능성 있음, 스크린샷만으로는 교정 케이스 확인 안 됨).
- **AI 발화**: 왼쪽 정렬, 텍스트가 스트리밍(타이핑)되듯 표시됨. 완료되면 영어 문장 아래 회색 작은 글씨로 한국어 번역이 함께 표시 (영한 동시 자막).
- **하단 통화 컨트롤 바**: 빨간 원형 "종료"(수화기 아이콘) / 회색 원형 "말하기"(마이크 아이콘, 눌러서 말하는 PTT 방식으로 추정) / 회색 원형 "주제"(도형 아이콘, 대화 주제 전환).

**8. 주제(topic) 선택 다이얼**
- "주제" 버튼을 누르면 뜨는 것으로 추정되는 원형 다이얼 오버레이(블랙, 블러 배경).
- 중앙에 현재 선택된 항목("나" — 사람 아이콘) + 설명("나의 성격과 가치관을 알아보는 질문") + "선택" 버튼.
- 방사형 메뉴 아이템: 나(사람) / 커리어(새싹) / 관계(하트) / 감정(스마일), 중앙 X로 닫기.

**9. 통화 종료 직후 요약 화면**
- 완전 블랙 배경에 거대한 숫자("139")가 화면 중앙에 크게 표시, 아래 필 라벨 "🔥 내가 말한 단어" — 통화 직후 "이만큼 말했다"를 임팩트있게 보여주는 축하/요약 스크린.

**10. 리포트 상세 화면**
- 상단에 **핑크색 긴급 배너**: "⏰ 할인 혜택이 곧 사라져요 04:43" (카운트다운 타이머, 실시간으로 감소 — 통화 직후 구독 유도 UX)
- 뒤로가기 + "···" 메뉴. 제목은 **AI가 생성한 대화 주제명**(예: "군대 동기와의 솔직한 대화") + 날짜.
- 스탯 필: "🔥139"(단어 수), 초록 필 "나의 유창성"
- 반원형 게이지 차트(0~100) — 복습 전에는 "?" + "아직 복습을 안했어요" 로 잠금 상태.
- 3개 스탯 카드: "발음" / "운율" / "유창" (복습 전 00%)
- 큰 검은 버튼 "복습하기"
- 섹션 "✨ 내게 딱 맞는 원어민 표현" — 캐러셀(예: 7개 중 1/7), 카드에 표현("get practice in") + 한글 뜻 + 예문(핵심 표현 부분 초록 하이라이트) + 북마크 + "🎤 연습" 버튼
- 아래로 스크롤하면 "통화 내용" 섹션(전체 대화 트랜스크립트, 리뷰 모드): 각 AI 말풍선 아래 4개 아이콘(깃발/스피커 재생/번역 토글/북마크), 사용자 말풍선에는 초록 "👍 패러프레이징" 태그.

**11. 표현 섀도잉(발음 연습) 모드**
- 스토리 형식 풀스크린(상단 X 닫기 + 세그먼트 진행바 + N/7 카운터 + 북마크).
- 중앙 스피커 재생 버튼 + 큰 영문 예문 + 아래 한글 번역.
- 하단 "따라 말해보세요" 툴팁이 빨간 마이크 녹음 버튼을 가리킴, 옆에 **눈 모양 아이콘**(스크립트 숨기기/보기 토글 — 유저가 요청했던 "스크립트 안 보이게" 기능이 이미 구현되어 있음).
- 녹음 후: 반원 게이지에 "Great!" 같은 등급 텍스트 + 문장을 단어별로 **초록/노랑/빨강**으로 색칠(발음 정확도별) + "🔊 원어민" / "🔊 나" 비교 재생 버튼 + 재시도(↺)/다음(→) 버튼.
- 상세 점수 바텀시트: "종합 점수" 반원 게이지(예: 96%) + 하위 지표 3개(발음 91% / 운율 99% / 유창 99%).

### 마이그레이션 중 발견한 실제 버그 2건 (둘 다 실행 검증으로 발견, 수정 완료)
1. **`useAsync` 훅이 렌더 중 ref를 변경**(`fnRef.current = fn`) — React Compiler가 `Cannot access refs during render`로 차단. `fn`을 ref에 담아 "항상 최신 fn 사용" 패턴 대신, effect가 실행되는 시점의 클로저를 그대로 쓰도록 단순화해서 해결(`deps`/`reload()`의 `tick`이 재요청 시점을 통제하므로 `fn` 자체를 deps에 안 넣어도 안전).
2. **로그인 게이트가 실제로는 동작하지 않음**: `export { auth as proxy } from "@/lib/auth"`만으로는 `req.auth`를 채워줄 뿐 비로그인 요청을 리다이렉트하지 않는다는 걸 실제 `curl` 테스트로 발견(비로그인 상태로 `/`에 접속했는데 200 OK가 옴 — 정적 검사로는 절대 못 잡음). NextAuth v5의 `callbacks.authorized`를 추가해야 Proxy에서 실제 리다이렉트가 동작함을 확인 후 수정 → 재검증: 비로그인 `/` 요청은 307 → `/sign-in`, `/api/data/persona`는 401.
3. **Next.js 16 `middleware.ts` deprecation**: 빌드 시 "middleware 파일 컨벤션은 deprecated, proxy 사용" 경고 발견 → `node_modules/next/dist/docs/.../proxy.md` 확인 후 `src/middleware.ts` → `src/proxy.ts`로 이름 변경, export도 `proxy`로 변경 (AGENTS.md가 경고했던 "이 Next.js는 아는 Next.js가 아니다" 케이스 그대로).

## 10차 갱신 (2026-08-21) — 사용성 피드백 4건 반영
사용자 피드백: (1) 응답이 10초 이상 걸려 느림 (2) AI 목소리를 실제 20대 여성 목소리로 (3) 마이크가 누르고 있는 동안만 녹음돼 불편 → 눌러서 시작/다시 눌러서 종료 방식으로 (4) 통화 기본 5분 후 연장 의사를 물어보고 원하면 3분씩 추가.

- **속도**: `src/lib/gemini.ts` — Gemini가 매 응답마다 내부적으로 "생각(thinking)" 단계를 거쳐 지연이 발생하는 걸 확인(간단한 응답에도 thoughtsTokenCount 100~180). 공식 문서상의 `thinkingConfig.thinkingBudget` 필드는 이 모델(`gemini-3.6-flash`)에서 **400 에러**가 나서 못 씀 — `curl`로 직접 여러 필드/값을 프로빙해서 `thinkingConfig.thinkingLevel: "MINIMAL"`이 실제로 동작하고 생각 토큰을 0으로 만든다는 걸 확인 후 적용. `maxOutputTokens`도 400으로 제한.
- **여성 목소리**: 신규 `src/lib/tts.ts` — 브라우저 `speechSynthesis`가 제공하는 음성 목록에서 젊은 여성 목소리를 휴리스틱으로 선택(선호 이름 목록 + "female"/여성 이름 키워드 매칭), pitch/rate를 살짝 조정. 클라우드 TTS는 네트워크 왕복이 추가돼 속도 목표와 상충되므로 채택 안 함. 통화 화면뿐 아니라 리포트 트랜스크립트 재생, 섀도잉 연습 화면의 원어민 재생까지 전부 이 공용 함수로 통일.
- **마이크 토글**: `call/page.tsx` — 기존 mousedown/mouseup(누르고 있는 동안만 녹음) → 한 번 탭하면 녹음 시작, 다시 탭하면 종료 후 전송하는 방식으로 변경. Playwright로 aria-label이 "말하기 시작"↔"말하기 종료"로 정확히 토글되는 것 확인.
- **통화 시간 5분+연장**: 기본 5분(`DEFAULT_CALL_SECONDS`) 도달 시 "5분이 지났어요, 3분 더 통화할까요?" 오버레이 표시 → "더 할래요"면 3분(`EXTEND_SECONDS`) 연장 후 계속, "종료할게요"면 바로 통화 종료. 통화 시계는 수신 화면이 아니라 **실제로 받은 시점**부터 재도록 `answerCall()`에서 재설정하도록 수정.

### ⚠️ 중요 발견: Gemini 무료 티어 일일 한도
속도 테스트로 `curl` 프로빙을 반복하다가 **`gemini-3.6-flash` 모델의 무료 티어 일일 한도(하루 20회, 프로젝트당·모델당)를 그날 소진**함 (`429 RESOURCE_EXHAUSTED`). 실사용 시 통화 한 번에 여러 턴(각 턴=API 호출 1회) + 리포트 생성(추가 1회)이 필요하므로, **하루 20회는 실사용에 상당히 부족할 수 있음** — 통화 3~4번이면 소진될 수 있는 수준. 유료 결제(Google AI Studio에서 결제 정보 등록)로 전환하면 한도가 크게 늘어남. 사용자에게 별도 안내 필요, 아직 결정 안 됨(열린 질문으로 남김).

사용자 요청: "전화 시스템의 딜레이가 최대한 줄었으면 좋겠어" (10차의 속도 개선 이후 추가 최적화).

- **모델+키 폴백 매트릭스**: 사용자가 "쓸 수 있는 모델이 여러 개"라고 알려줘서 검토 → 실제로 무료 티어 한도는 **모델별로 독립적**임을 `curl`로 재확인(`gemini-3.6-flash` 소진 상태에서도 `gemini-3.5-flash`/`gemini-3-flash-preview`/`gemini-3.1-flash-lite`는 정상). 추가로 사용자가 준 **두 번째 API 키도 완전히 독립된 할당량**을 가진 걸 확인(`gemini-3.6-flash`가 첫 번째 키에서 소진된 상태에서도 두 번째 키로는 성공). `src/lib/gemini.ts`를 모델×키 조합을 순서대로 시도하는 폴백 매트릭스로 재작성 — `GEMINI_API_KEY_2` 환경변수로 두 번째 키 추가 가능.
- **응답 시간 편차 문제 발견 및 대응**: "생각(thinking)"을 꺼도 Gemini 원본 응답 시간 자체가 동일 모델·동일 키로 반복 호출해도 **1.5초~20.7초까지 들쭉날쭉**함을 `curl`로 확인(서버 부하에 따른 변동으로 추정, 우리 코드 문제 아님). 대응: `AbortController` 기반 **요청당 4.5초 타임아웃**을 걸어 느린 시도는 바로 다음 모델/키로 넘기고, 전체 폴백 과정에 **11초 하드 데드라인**을 둬서 무한정 기다리지 않고 기존 "다시 시도" UI로 넘어가게 함.
- **부가 지연 요소 2건도 제거**: (1) AI 응답의 타이핑 애니메이션이 응답 길이와 무관하게 항상 ~1.1초 걸리던 것을 ~450ms로 단축. (2) TTS 음성 목록 조회(최초 1회 최대 400ms)를 통화 화면 마운트 시 미리 시작(`preloadVoice()`)해서 인사말 요청과 병렬로 처리, 첫 발화 재생에 지연이 더해지지 않도록 함.
- **라이브 검증**: 반복 호출 시 `application-code` 처리 시간이 1.4~2.4초로 안정화됨을 확인 (이전엔 최대 20초 이상까지 튀었음).

### 사용자가 확인할 것
- **Vercel 배포본에도 `GEMINI_API_KEY_2` 환경변수를 추가**해야 배포 환경에서도 두 번째 키 폴백이 적용됨 (로컬 `.env.local`에만 있으면 로컬에서만 효과 있음)
- Gemini 무료 티어 한도 자체는 여전히 존재 — 이번 변경은 "있는 한도를 최대한 활용"하는 것이지 한도 자체를 없애는 건 아님. 유료 전환 여부는 여전히 열린 질문.
